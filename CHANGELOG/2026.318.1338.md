## Summary

Two lines in the runner bed are dead, and this PR deletes them (R5) — plus the two comments that named the variable they set.

**Where, exactly** (head `97fc811`, 1 file, +5/−9 across three commits): the **root `charly.yml`**, in the `check-fireactions-runner-vm` bed's `runner-image-builds` step —

```yaml
-                CHARLY_PLUGIN_DIR=/tmp/charly-plugins
-                export CHARLY_PLUGIN_DIR
```

The comment rewording is the same commit: the two places that described `CHARLY_PLUGIN_DIR` as "the thing that points the loader at the delivered tree" now say what happens — the loader finds the tree the `plugin-tree:` step left.

**Measured, not assumed.** The lines were added when the delivery route had not landed, so a `cloud_image` guest had to point the loader at the tree by hand. Delivery landed (`plugin-deploy-firecracker:v2026.318.0132`) and the bed passes **without** them:

That run was taken on the tree of `35d4126` — the two lines deleted, nothing else touched. `ab4b0e1` then changes **prose in two comments** and no command, and `97fc811` is an EMPTY re-trigger commit (no tree change) that was needed because the previous gate run on this head was cancelled and a cancelled same-name check blocks the merge. So the executed tree the run covers is this head's tree, byte for byte, in everything the gate runs.

**Repo-scoped sweep** (the whole repo, not one file — the previous round's finding):

```console

I withdrew the claim on `#977` (`issuecomment-6877661066`) and this PR removes the leftover it leaves behind.
